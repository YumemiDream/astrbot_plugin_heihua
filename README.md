# 黑话词典 astrbot_plugin_heihua

听得懂群里的黑话。只做这一件事。

> AstrBot 插件 · 适配 AstrBot `>=4.20,<5` · 无第三方依赖 · 自带插件页

从零重写的轻量黑话插件，参考了 `astrbot_plugin_self_learning` 的黑话功能（也只参考了它，
其余臃肿功能一概不要）。旧插件的黑话库被大量"一眼就懂"的词污染——笨蛋、晚安、点赞、
群规、the、to、false、help——还有 `7B%`、`22%` 这种垃圾 token 和成片的
"可能是指 X，也可能是 typo……"式脑补释义。本插件从设计上根治这些问题。

## 设计哲学

**什么才算黑话？只有一条标准：局外人测试。**

> 一个不在该群的普通网民，看到这个词，无法明白它在群里的意思。

`笨蛋` 过不了测试（谁看不懂？）、`yyds` 也过不了（全网流行）、`the` 更不行。
`抛瓦`（power 谐音）、`雪团`（群里给 bot 起的外号）可以通过。
拿不准的边界词不进兜底黑名单，交给局外人测试 + 证据门禁去判断。

**四条质量底线：**

1. **局外人测试** —— Prompt 里定义清晰，外加二次甄别复审（可关），杜绝"一眼懂"词汇入库；
2. **证据约束** —— 词条和例句必须逐字出现在聊天记录里（本地校验），LLM 编不出来；
3. **反脑补** —— 释义含"可能/大概/typo/likely…"等推测措辞的，整条丢弃。与其存一条
   猜测的垃圾释义，不如不存，等下次上下文够了再学；
4. **宁缺毋滥** —— 一次最多收 5 个词，反复出现（≥2 次）的才收。想要的随时手动教，人工词条
   自动挖掘永不覆盖。

对比旧实现：没有统计过滤器、没有 jieba 词频表、没有三步推断（一次挖掘 2 个小 LLM 调用封顶）、
没有 3/6/10/20/40/60/100 阈值推断、没有 usage_frequency 表。
词库就是一个 JSON 文件，核心逻辑 4 个 Python 文件；WebUI 只有一个静态页面（无构建步骤）。

## 安装

在 AstrBot 仪表盘 → 插件 → 安装插件，填入仓库地址：

```
https://github.com/YumemiDream/astrbot_plugin_heihua
```

或手动克隆到 `data/plugins/` 后重启 / 重载插件：

```bash
cd AstrBot/data/plugins
git clone https://github.com/YumemiDream/astrbot_plugin_heihua.git
```

## 用法

命令需要唤醒前缀（默认 `/`）或 @ 机器人。

| 命令 | 说明 |
| --- | --- |
| `黑话 <词>` | 查释义 |
| `黑话 <词>=<释义>` | 教黑话（同 `学黑话`） |
| `学黑话 <词>=<释义>` | 教黑话（也支持 `学黑话 <词> <释义>`） |
| `学全局黑话 <词>=<释义>` | 教全局黑话（管理员，所有会话可见） |
| `删黑话 <词>` | 删除词条（管理员） |
| `黑话列表 [页码]` | 浏览词典 |
| `黑话重学` | 立即挖一次（管理员） |
| `黑话开关` | 开关自动挖掘（管理员） |

**作用域规则（二值，无私聊层）：**

- **群里**：查询看「全局 + 本群」；教黑话只写本群词库（影响面=本群，人人可教）
- **私聊**：查询/理解走全局词典；教黑话即写全局（影响面=全局，**仅管理员**）
- 同名词条：本群覆盖全局——群内特指含义优先，且不会串到别的群

机器人回复时若用户消息命中黑话，会自动在 LLM 请求里注入一行对照：

```
[黑话对照] 「抛瓦」=power 的谐音，指实力、火力；「雪团」=群里对机器猫的昵称。以上仅供理解用户在说什么，回复时不必刻意使用这些词。
```

## 专属管理页面

仪表盘 → 插件 → 黑话词典，自带一个插件页面（`pages/dict`）：

- 词条总览：总数 / 人工 / 自动学习 / 累计命中
- 词典管理：按作用域浏览、搜索、新增、编辑、删除，**分页浏览**（每页 20 条）
- **作用域开关**：每行一个开关，开着=全局、关掉=局部；关掉时自动回到词条所属的群，改错可 6 秒内撤销
- **命中记录**：最近 30 次「什么时间、哪个群、哪句话命中了哪些词、注入到 prompt 还是 system_prompt」的完整记录
- 挖掘控制：查看各群采样进度、手动触发挖掘、开关自动挖掘
- 一键导出词库 JSON

后端 API 经 `context.register_web_api` 注册（`page_api.py`），挂在仪表盘登录之后。

## 数据

词库在插件数据目录的 `jargon.json`（`data/plugin_data/astrbot_plugin_heihua/`），
结构可读可手改，含 `global`（全局）与 `groups`（各群）两层（无私聊层），
群内词条覆盖同名全局词条。条目字段：`term / meaning / example / source / added_by / created_at / updated_at / hits / home_scope`。

命中记录在同一个目录的 `hits.json`（环形缓冲，只留最近 30 次，落盘做了 10 秒节流）。

## 配置

见插件配置页。常用项：自动挖掘开关、挖掘间隔、单次入库上限、二次甄别、仅管理员可教。

## 从旧插件迁移

不自动迁移旧数据（旧库污染严重，不值得搬）。建议：
1. 停用或卸载 `astrbot_plugin_self_learning`（或至少关掉它的黑话学习，避免双份注入）；
2. 对有价值的旧词条手动 `黑话 词=释义` 补录；
3. 开着自动挖掘，让它从头学一份干净的。
